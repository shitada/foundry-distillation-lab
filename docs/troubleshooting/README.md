# トラブルシューティング

まず新しいrunに分離し、入力・版・エラーの最小情報を保存します。既存結果の削除、承認guardの無効化、成否不明の再送から始めないでください。

| 症状 | 調べること | 安全な次の一手 |
|---|---|---|
| `python`が見つからない/別の版 | `py -3.13 --version`、使用した実行ファイル | READMEの仮想環境Pythonを直接指定する |
| `ModuleNotFoundError` | cwd、`pip`とPythonが同じ環境か | ルートで`.\.venv\Scripts\python.exe -m pip install -e .` |
| PowerShellのactivateが拒否される | 実行ポリシー | ポリシーを緩めず`.\.venv\Scripts\python.exe`を直接使う |
| 出力先が既に存在する | そのrunが完了/部分出力か | 新しいrun名を指定。元は監査用に保持 |
| JSON入力エラー | JSON構文、型、`null`と文字列の違い | スキーマと比較。NaN/Infinity/負数は使わない |
| cache検査エラー | cache tokenがinputの内数か | 全呼出しを同じ単位で集計。総入力に再加算しない |
| レポートの合計が`null` | 未知のusage/単価/費目 | 根拠を取得するまで保留。ゼロ埋めしない |
| 図に線がない | 未知費目による不明系列 | JSON/CSVを読む。0円の線ではない |
| baseとfine_tunedの線が同じ | 仮想例の変動費/固定費が同額 | 初期込み`payback.svg`とCSVで区別 |
| 成功単価が空欄 | レビュー未了、成功0、要求0 | 未定義が正しい。自動合格を人間レビューにしない |
| 自動採点と人間判断が違う | 説明・状態・必須順序の証拠 | 両方保存。期待値を変えて緑にしない |
| データ漏洩/カテゴリ欠落 | 会話・注文・意味重複、生成テンプレート | 分割設計を見直し、別versionで再生成 |
| SDK import/引数の不一致 | コントロールとHosted Agentのmajor | 依存を分離し、公式SDK契約と確認済み版を記録 |
| 認証/region/quotaの失敗 | 別途承認したpreflight結果 | 環境問題として記録。モデル品質の失敗に混ぜない |
| timeout直後にjob状態不明 | 送信前journal・request/job ID | 送信せず照合。二重jobを作らない |
| ローカル停止後も費用が出る | 学習job・hosting・保存資源の状態 | 所有が証明された資源だけ明示的に停止/cleanup |

## 診断の順序

1. **オフラインかliveか**を切り分ける。helpやmockの合格はlive成功ではない。
2. 入力hashとcontract、Python/SDK版、実行コマンドを確認する。
3. 予定件数、未試行、基盤障害、モデル失敗を分け、母数を保持する。
4. 最小の再現テストを追加してから修正する。
5. 同じ固定条件で回帰テストを実施する。実験条件を変えた場合は別runにする。

## 提出してよい診断情報

匿名化したエラー種別、パッケージ版、オフライン最小入力、公開サンプルでの再現手順を共有します。credential、token、認証cache、個人endpoint、顧客データ、生ログ、承認ファイルを貼り付けないでください。

クラウドのPreview API、モデル提供範囲、SDK契約は変わります。未確認のフラグや廃止されたStored Completions経路で回避せず、公式資料と照合して新しい検証計画を立てます。本教材はlive未検証であり、プロバイダーの障害対応手順の代わりにはなりません。
