# 実験条件・実行記録・停止

## オフラインとクラウド実行

データ整形、保存済み結果の採点、図表の生成にはクラウド資格情報は不要です。
学習やモデル呼び出しの前には、対象・入力・呼び出し上限と費用見積りを確認します。
学習費だけでなく、推論費・配置の保持費と終了予定も確認してください。
見積りと取得できた使用量・実費は区別し、欠落を0とは扱いません。

入力・設定のsnapshotとサービスの受付記録（receipt）は自動保存されます。
内部の識別値や送信記録は、取り違え・重複送信を防ぐためのものです。
利用者が手作業で識別値を計算したり、実行許可のJSONを作ったりする必要はありません。
これらはAzureの課金上限や、ローカル停止後のクラウド課金停止を保証しません。

## 成否不明時に再送しない

送信前に記録を保存し、既存結果を上書きしません。通信切断や結果保存の失敗では、
要求が受け付けられたか分からないため、自動で送り直しません。
runを削除・改名して再開するのではなく、receiptやサービス側の一覧で元の要求を確認します。
学習の`status`は読み取り専用で、待機の時間切れは学習のキャンセルではありません。

評価は最初の通常ケースで接続も確認し、その使用量・時間を本評価に含めます。
失敗や呼び出し上限で停止した場合、未試行のケースも評価の分母へ残します。

## 内容の確認と比較条件

実行する判断と、結果の内容を人が評価することは別です。
自動採点が通っても、説明の正しさや必要な確認を人が読むまでは確認待ちです。
確認結果は`reviews.csv`へ記入し、`review`コマンドで保存します。

入力、指示文、ツール、生成条件を変えた場合は、変更内容と理由を残します。
期待値だけを都合よく変えて既存結果を合格にしません。
学習・検証・改善用評価・最終評価の分割を維持し、最終評価を候補選びに使いません。
最終評価を見て改善した場合は、新たな独立最終評価が必要です。

## 後片付け

自分のrunが作ったと確認できる資源だけを対象にし、保存する記録と保持費を確認して削除します。
共有の教師モデル、他人の配置、学習原本を一括削除しません。
削除要求の受付、サービス上での不在確認、請求の確定は別の状態です。
