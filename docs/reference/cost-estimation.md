# 実験記録と公開単価による費用グラフの自動生成

第8章の`report.py --estimate`は、公開小売単価と保存済みの使用量を使い、ラボの成果物となる費用グラフを生成します。Azure Cost Management、請求明細、契約割引、税、為替は取得しません。通貨はUSDで統一します。

## 入力と実行

```powershell
.\.venv\Scripts\python.exe scripts\report.py --estimate
```

設定ファイルは省略できます。既定値は追加初期費用0、追加月額費用0、ホスティング時間1日24時間です。変更する場合は`configs\examples\cost-plan.json`を複製し、`--config runs\cost-plan.json`で指定します。明示的に指定したファイルが存在しなければエラーになります。

| 設定項目 | 意味 |
|---|---|
| `additional_initial_cost` | 学習済み構成の導入に追加でかかる初期費用。USD、0以上 |
| `additional_monthly_cost` | 学習済み構成の運用に追加でかかる月額費用。USD、0以上 |
| `hosting_hours_per_day` | 将来のホスティング保持時間。1日0〜24時間 |

設定の一部だけを指定した場合、残りは既定値を使います。追加費用の0は人件費などを未計上とする前提であり、実際に無料だったという記録ではありません。`monthly_requests`・`horizon_months`や表示範囲、モデル別の追加費用は、この自動生成コマンドの入力項目ではありません。

標準では`runs`から記録を探し、`runs\cost-report`へ出力します。別の場所で実験した場合は`--runs-dir`、出力先を指定する場合は`--output`を使います。同名の出力先が存在すれば、連番付きの新しいフォルダーを作ります。

第7章の選択結果が壊れているなど、三つの評価結果を統合できない場合は停止します。単価や使用量の一部が不明な場合は、部分的な費用レポートと不足情報を保存し、終了コード2を返します。費用入力が揃えば0を返します。終了コードは品質の合格や採用の判定ではありません。

## 実験記録の対応付け

最後に開始した第7章の実験を、記録した開始時刻で選びます。結果が良かった実験を探して選ぶことはしません。選択した実験の三つの採点結果を統合し、一件あたりの使用量と品質の情報を取り込みます。

初期費用には、その実験のデータ・モデルと結び付けられる教師データ生成、学習、評価、採点の記録を含めます。個別のモデル呼び出しは送信前・送信後の記録で追跡し、結果を複製したファイルや、同じ学習ジョブの状態確認を別の課金として重複計上しません。

応答のない送信記録、未取得の使用量、関連付けられないデータ生成記録は、不足として表示します。同梱のスクリプト生成サンプルは教師モデルを呼んでいないため、そのデータ生成費を0として区別できます。

読み取ったファイル、選択した実験、除外した記録と不足情報を`inventory.json`へ保存します。実験以外の作業や、記録の残っていない過去の支出まで自動推測しません。

## 配置と公開単価

現在Azure CLIで選択しているサブスクリプションから、評価に使った接続先に一致するAzure OpenAIリソースと配置を読み取ります。モデル名・版・地域・配置方式を取得し、公開料金の候補と照合します。設定済みのアカウントで読み取りができない場合や、対象が曖昧な場合は、その理由を残します。

料金の取得元は[Azure Retail Prices API](https://learn.microsoft.com/rest/api/cost-management/retail-prices/azure-retail-prices)です。モデル、地域、通常モデルと学習済みモデルの区別、配置方式、料金の単位、適用開始日を確認します。見つからない料金を近いモデルの単価で補ったり、複数の候補から無条件に最安値を選んだりしません。

現在の公開単価を過去の使用量にも適用します。取得時点の価格で同じ条件の比較を行うもので、過去の請求金額の再現ではありません。取得した配置情報と使用した料金の根拠は`prices.json`へ保存します。

標準の対応対象は`gpt-5.5`、`gpt-4.1`、`gpt-4.1-nano`と識別できる学習済みの`gpt-4.1-nano`です。通常料金と、一括処理・優先処理などの料金を区別します。公開料金の取得が制限された場合や、対象の料金項目を特定できない場合は、不足として報告します。

`gpt-5.5`は入力長で単価が変わるため、保存した各呼び出しの入力トークン数で料金区分を選びます。27万2,000トークンを超えるかどうかの境界は、[提供元のモデル料金説明](https://developers.openai.com/api/docs/models/gpt-5.5)に基づきます。月額の見積もりに使う呼び出しに料金区分が混在する場合は、一律の単価で平均を価格換算せず、不明として残します。

現在の配置のモデルと、保存された応答のモデル識別子が食い違う場合も、過去の呼び出しを現在の別モデルの料金で計算しません。

## 費用の計算

| 対象 | 計算方法 |
|---|---|
| モデル推論 | 入力の通常分、再利用分、出力に対応する単価を掛けて合計 |
| 学習 | 学習ジョブから取得した`trained_tokens`と、モデル・学習方式に対応するトークン単価を使用 |
| 月額ホスティング | 時間単価に`hosting_hours_per_day × 365 ÷ 12`を掛ける。既定の24時間では月730時間 |
| 実験中のホスティング | 現在の配置の作成時刻から概算時点までの経過時間に時間単価を掛ける |
| 利用者の追加費用 | 学習済みモデル構成の追加初期費用・追加月額へ加算 |

`trained_tokens`に学習の繰り返し回数を再度掛けません。対象の学習方式が時間課金などで、記録と料金の単位が対応しない場合は学習費を不明とします。

初期費用の配分は、比較のための評価・採点費を三つの構成へ均等に配分し、教師データ生成と学習は`fine_tuned`へ計上します。これに各構成の記録できた実験中のホスティング費と、学習済み構成への追加初期費用を加えます。生の費用と配分先は`cost-ledger.json`で確認できます。

ホスティング時間の指定は将来の費用見積もりに適用します。実験中の費用は記録された実際の保持期間を使い、指定を変えて過去の支出を減らすことはしません。Azure上の配置・稼働時間を変更する操作も行いません。

学習済みモデルの過去の配置を既に削除している場合、その配置情報や保持期間を現在の配置から復元できません。記録不足の範囲を明記し、分かる範囲の概算として扱います。

この教材は手元の業務ツールを動かすため、専用のクラウドエージェント基盤や外部業務ツールの利用料は標準の自動計算に含めません。学習済み構成に追加で必要な運用費や人件費は上記の二つの費用項目に入力します。

## 自動で決めるグラフの条件

月額費用は月間問い合わせ件数を横軸として描きます。計算できた分岐点を基に、その前後と三つのモデルの差が見える範囲を選びます。累積費用は自動選択した複数の月間件数で描き、それぞれの件数と表示月数を明記します。

表示範囲は費用を有利に見せるためではなく、読みやすさのために調整します。回収期間が表示上限を超える場合、分岐点がない場合、計算する情報が不足する場合を区別して表示します。選択した範囲とその理由は`graph-plan.json`に保存します。

月額の正の交点が得られる場合は、最も大きい交点の前後を含む三つの件数を選び、読みやすい数値に丸めます。交点を決められない場合は、月100件・1,000件・10,000件を比較用の仮定として使います。これらは利用実績や費用の仮想値ではありません。

累積費用の表示期間は、計算できた正の回収期間の約1.5倍を目安に選びます。短期間で回収する場合は1か月などの範囲で表示し、正の回収期間が得られない場合は12か月を使います。表示期間の上限は1,200か月です。描画点は原則80区間と正確な交点に限り、月額の交点や累積費用の交点には印と補助線を付けます。

各図では同じ金額・使用量・料金を使い、利用件数の仮定だけを変えます。自動選択した件数は実際の業務量の推定ではありません。`costs.csv`や従来形式の`report.json`の月額は、自動選択した代表条件に対応します。複数の条件の結果はグラフと生成計画に保存します。

## 出力

- `graphs.md`：主な成果物。今回の費用グラフをまとめたページ。
- `costs.csv`、`volume.svg`、`cumulative.svg`、`payback.svg`：費用比較の表と図。
- `graph-plan.json`：自動選択した件数・期間・表示範囲と選択根拠。
- `report.json`、`input.json`：計算結果と、それを再計算するための入力。
- `estimate.md`、`estimate.json`：概算の範囲、選択した実験、計算条件と不足情報。
- `prices.json`：配置情報、公開単価と取得根拠。
- `inventory.json`、`cost-ledger.json`：読み取った実験記録と、費用の配分。
- `combined`フォルダー：第7章の三つの採点結果を統合した記録。

グラフには`PUBLIC RETAIL ESTIMATE; NOT INVOICE`と表示します。不明な値を0へ置き換えず、採点用モデルの使用量も顧客対応の使用量とは分けます。自動採点を人間確認済みの成功として扱わず、採用の判断は保留から始めます。

既存の`report.py --prepare-evaluation`と`report.py --input ... --output ...`は、保存した料金・費用入力からオフラインで計算する用途として引き続き使えます。
