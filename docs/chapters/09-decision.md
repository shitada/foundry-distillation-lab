# 09 蒸留をどこに使うか――実験から次の展開へ

## この実験で分かった、蒸留が役立つ条件

このラボでは、小売サポートの対応を教師から生徒へ学習させ、判断の変化と問い合わせへの対応全体を評価し、費用グラフを作りました。

そこから考えたいのは、**どの仕事を、どの利用条件なら、そのモデルに任せられそうか**です。返品対応が改善していても、重要な確認を省く場面が残るなら、その対応を任せる範囲を見直します。品質を満たしていても、利用が少なく固定費の影響が大きければ、費用面の利点は小さくなります。学習前から十分に対応できていれば、追加学習をしない構成も有力です。

**蒸留は、任せたい仕事を絞り、その範囲で品質と費用の釣り合いを改善する方法です。** 学習前の生徒を測ったのは学習の意味を確かめるため、二つの評価を使ったのは判断の改善と仕事の完了を分けるため、グラフを作ったのはその変化が経済的な意味を持つ条件を見るためでした。

今回得たのは、評価した問い合わせと実行条件の範囲での結果です。その範囲を出発点に、次の二つの方向を考えられます。

## 期待した結果が出なかったときの選択肢

### 何が改善しなかったのかを分ける

品質が上がらなかったときは、まず採点や参照例が業務ルールに合っているかを確認します。そのうえで、結果の現れ方から次に調べる方向を選びます。

| 結果の現れ方 | 次に調べること |
|---|---|
| 教師の回答に誤りや矛盾がある | 学習例の正しさと一貫性 |
| 特定の依頼や条件だけ苦手 | その条件を扱う学習例の不足 |
| 学習例に似た問題はできるが、別の問題で崩れる | 例の多様性と、学習用・評価用データの分け方 |
| 個々の判断は改善したが、対応全体で崩れる | 長い処理の流れ、指示文、ツールの使い方 |
| 品質は改善したが、費用面の利点が小さい | 利用量、固定費、追加学習にかける費用 |

例えば「学習後は返品手数料を正しく説明した」は応答から確認できる事実です。「手数料の学習例が役立った」は原因についての推測です。推測を確かめるときは、変更する点を絞り、同じ基準で比較します。

### データの質を上げるか、数を増やすか

返品期限を過ぎても無条件で返金するような誤った例が混ざっているなら、先に内容を直します。同じ業務条件で異なる判断をする例があれば、その理由を確認し、手本を一貫させます。

一方、通常の返品例は正しくても、最終処分品、会員区分、遅配などの条件が少なければ、不足する例を追加する意味があります。表現だけを変えた似た会話を大量に増やすより、判断に必要な条件の違いを含めることが重要です。

**質の改善は、教える内容を正しく一貫させること。量の追加は、必要な状況を十分に経験させることです。**

データを増やすときは段階的に増やし、固定した改善用の評価で品質と追加費用の変化を比べます。最終確認用のデータは、学習例や設定を選び終えた後に使います。正しい例を増やしても改善が小さければ、生徒モデルの能力や、任せる仕事の複雑さを見直します。

### 学習以外の手段を選ぶ

教師ありファインチューニングを続けるかは、改善の見込みと費用で判断します。

| 課題 | 考えられる手段 |
|---|---|
| 指示の解釈が曖昧 | 指示文を具体化する |
| 最新の注文情報や業務規則が必要 | ツールから必要な情報を取得する |
| 決まった処理順序を守れない | 必須の処理順序をプログラム側で管理する |
| 複雑な判断が生徒モデルの能力を超える | より適したモデルへ変える、任せる仕事を絞る |
| 学習前から必要な品質を満たす | 学習前のモデルをそのまま使う |

学習は、指示文・ツール・モデル選択の改善と並ぶ選択肢です。どの手段を選んでも、対応全体の品質・時間・費用を測るという考え方は共通です。

## 得意な仕事を分担する構成へ広げる

小型モデルが一部の仕事に十分対応できるなら、その範囲を担当させる構成も考えられます。例えば、配送状況の照会は生徒モデル、複数の商品や条件が絡む相談は高性能モデル、判断材料が足りない重大な処理は人に引き継ぐ方法です。

この構成では、**モデルの回答だけでなく、依頼を適切な担当へ送る判断も評価対象になります。** 難しい依頼を生徒モデルが抱え込むことと、簡単な依頼まで高性能モデルへ送ることの両方を確認します。振り分けには依頼の種類や明示的な条件、実行結果などを使い、実際に適切な引き継ぎができるかを測ります。

費用と時間には、振り分けの処理と、引き継ぐ前後の呼び出しをすべて含めます。生徒モデルが対応を試した後に教師へ引き継ぐなら、両方の費用がかかります。単独のモデルを置き換える場合と、役割分担する場合を、同じ問い合わせで比べることが大切です。

蒸留の価値は、教師モデルの全面的な置き換えだけにあるのではありません。**生徒モデルが得意な仕事を担当することで、構成全体を効率化できる可能性があります。**

実運用へ進む際は、採用する実行環境と実際の業務を代表する問い合わせで、この構成全体を確かめます。別の業務へ応用する場合も、業務ルール・ツール・期待する対応を用意し、同じ比較の流れを使えます。

## ラボを終えて

このラボで作ったグラフは、小型モデルが安いという一般論ではなく、今回の品質と実行条件を前提に、費用面の利点が生まれる条件を示すものです。

任せる仕事を定め、学習前と比べ、実際の対応と費用を測る。この順序を繰り返すことで、モデルの名前や大きさだけに頼らず、仕事に合う構成を選べるようになります。

**成果物は比較表と費用グラフであり、そこから持ち帰るのは、蒸留をどこに使い、次に何を確かめるかを判断するための考え方です。**
