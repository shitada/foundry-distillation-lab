# 01 蒸留で何を達成したいか

## 現在地
まだ学習しません。最初に「どの仕事を、どの品質で、いくらで提供したいか」を言葉にします。

## 目的
蒸留はteacherの出力や行動を手本にstudentへ特定の仕事を学習させることです。本教材はFoundry上のteacherの**回答・ツール呼び出し履歴を使うSFT**を扱います。teacherの内部パラメーターや非公開の思考を複製することでも、あらゆる能力を移植することでもありません。

## 前提
APIでモデルに要求し応答を得る経験があれば始められます。SFTは正解例から応答を学ぶ方法、traceは一連の呼び出し履歴です。teacherも誤るため、履歴はそのまま正解になりません。

## 実施内容
次の流れを紙に写し、各矢印の前に停止条件を書きます。

```text
業務contract・評価基準を固定
  → teacher履歴を収集 → 品質確認・分割
  → teacherとbaseの評価 → studentのSFT
  → 評価① 次の行動 → 評価② 業務全体と人間レビュー
  → 品質を満たす候補だけ費用検討 → 採用 / 条件付き / 見送り / 保留
```

teacherは手本を作るモデル、baseは未学習student、fine_tunedは学習済みstudentです。baseで十分ならSFTしない選択もできます。学習費を先に払うことと、将来の運用費が減ることは別問題です。

架空のteacher20円/件、student2円/件＋月固定9,000円では、500件/月でどちらも10,000円です。1,000件/月ならteacher20,000円、student11,000円。さらにstudentに追加初期費用18,000円があると、差額9,000円/月で2か月後に回収します。

| 説明用件数/月 | teacher月額 | student月額 |
|---:|---:|---:|
| 100 | 2,000円 | 9,200円 |
| 500 | 10,000円 | 10,000円 |
| 1,000 | 20,000円 | 11,000円 |

これはAzure料金でも実測性能でもありません。[3種類の再生成可能な図表](../../examples/illustrative/README.md)で、月額の交点、初期費用を除く累積、初期費用を含む回収を見分けます。

## 出力
「返品を誤実行しない」「必要な確認を省かない」などの品質条件と、件数・許容待ち時間・予算の仮説を1枚に記録します。数字のない「安くて高品質」は実験目標にしません。

## 解釈
費用曲線は品質が同じであることを証明しません。まず品質、その後に時間と総費用を比較します。グラフで線が下にあるだけでは採用できません。

## 完了条件
蒸留の目的、コピーしないもの、3者、2種類の費用の問いを自分の言葉で説明できれば次章へ進みます。

## 限界
小売の限られた分布で学んだ行動が別業務でも通用するとは限りません。蒸留が成功するとの仮定を置かず、未学習モデルの勝利も記録します。
