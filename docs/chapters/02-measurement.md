# 02 測定を先に設計する

## 現在地
まだ結果を見ていません。この時点で比較条件と許容差を固定します。

## 目的
良い回答の印象ではなく、再現可能な証拠から学習の効果を判断します。teacher / base / fine_tunedを同じケース、contract、ツール、カテゴリ比で比較します。

## 前提
評価①は固定された履歴の「次の行動」、評価②は一つの顧客入力から始まる「業務全体」です。①の一致率が高くても、その行動の積み重ねが安全な②になるとは限りません。

## 実施内容
以下を実験計画に記入します。閾値は業務責任者が結果を見る前に決め、教材の例を承認済み数値とみなしません。

| 指標 | 何を測るか | どう使うか・注意 |
|---|---|---|
| 次の行動一致 | 応答/ツール選択、引数、形式 | 学習の局所的変化を診断。teacherの誤りも点検 |
| 必須フロー遵守 | 検索・確認・操作の順序 | 省略や不正順序の検出。全履歴の完全一致は要求しない |
| 業務成功 | 最終状態と日本語説明、必要な確認 | 自動判定と人間確認済み成功を別々に集計 |
| 安全性 | 不正要求、ツールで拒否された要求、実際の不正変更 | 3種類を混ぜず重大失敗を独立したゲートにする |
| 確認質問 | 情報不足時の適切な質問 | 解決可能なのに質問した場合と区別 |
| 時間 | 各要求の開始から最終応答まで、中央値とp95 | ツール待ち、再試行、cold start、失敗打切りを記録 |
| usage・費用 | 全モデル呼出しのtoken、cache、固定費 | 失敗・回復も含める。欠測を0にしない |
| coverage | 試行、未試行、失敗、カテゴリ別件数 | 少数の成功だけを分母にしない |

実験設計テンプレート：目的／モデルとversion／contract hash／業務日／ケース版／カテゴリ比／反復回数／最大step／品質閾値・許容差／費用上限／保留条件／人間レビュー担当／最終holdoutの保管先。

学習、検証、改善用評価、最終評価を分けます。最終holdoutは最後まで見ず、改善には使いません。最終評価を見て修正したら、それは改善用に降格し、新しい未使用holdoutと実験版で評価し直します。

## 出力
上記の計画と、分子・分母・欠測・レビュー状況を含む成績表のひな型です。平均だけでなくカテゴリ別失敗例を残します。

## 解釈
同じケースを比較しても少数サンプルや反復不足では同等性を主張できません。許容差と不確実性を併記し、差が見えないことを同等の証明にしません。

## 完了条件
結果が悪かった場合にも変えない基準、比較不能なら止める条件、最終holdoutを誰が守るかが決まっています。

## 限界
日本語の説明内容は文字列一致だけで保証できません。自動採点は暫定であり、未レビューの成功率を確定成績や成功単価へ変換しません。
