# コーディングエージェントを実行補助に使う

特定の有料拡張、個人skill、元のチャット履歴は不要です。エージェントは環境調査・実行・エラーの切り分けの補助であり、品質基準の決定者でも支出承認者でもありません。

## オフライン実行を依頼する

> このリポジトリのREADMEと対象章を読んでください。Windows / PowerShellとPython 3.13を使い、既存の仮想環境を確認し、標準unittestを実行してください。クラウド呼出し、credentialの表示、有料操作、git操作はしないでください。失敗時は最小の再現テストを特定し、変更前に原因を説明してください。結果は実行したコマンドと確認範囲で報告し、未実施を成功と言わないでください。

## 費用の練習を依頼する

> `examples\illustrative\cost-input.json`と費用スキーマを読み、`scripts\report.py`で新規run先へ出力してください。既存結果を上書きしないでください。500件/月の運用分岐と月1,000件・追加初期18,000円での2か月回収をCSVから確認してください。架空値でありAzure料金や品質の証拠ではないと明記してください。

## エラー調査を依頼する

> `runs\<run-id>`の公開可能なエラー部分だけを使い、入力不備、環境/依存、実装不具合、クラウド基盤、モデル行動のどれかを切り分けてください。個人IDや秘密情報は出力しないでください。再送はしないでください。送信済みか不明ならjournalを保存し、状態照合が必要と報告してください。

## 変更してよいもの・勝手に変えてはいけないもの

| 種別 | 扱い |
|---|---|
| import、パス、文字コード、依存不整合 | 最小修正と回帰テスト。版・コマンドを記録 |
| 業務ロジックのバグ | 独立した仕様を根拠に修正。旧結果を保持し、新版で再評価 |
| 学習例・prompt/tool・モデル | 実験条件の変更。新version/hashとrunが必要 |
| 正解・閾値・重大失敗条件 | **合格させるために変更しない**。真の正解誤りなら根拠とレビューを伴い3者を再評価 |
| 費用・成功率の欠測 | `null`や未レビューを維持。推測した0で穴埋めしない |
| 最終holdout | 改善には見せない。見たら新しい独立holdoutが必要 |
| 学習・推論・配置・cleanup | オフライン修正とは別権限。対象・上限・期限を結び付けて承認 |

調査のためにテストを消す、期待値を実装の現状に合わせる、予算guardを無効化する、成否不明の要求を再送する、といった修復は許可しません。エージェントの「修正済み」だけでなく、差分・テスト・出力の証拠を確認します。

## 報告テンプレート

「実行環境／入力・条件hash／実行コマンド／オフラインか通信ありか／確認結果／未確認／変更理由／再実行時の注意」を残します。cloudのmockと実環境成功を明確に区別します。支出や個人情報を伴う次の操作へ勝手に進ませないでください。
